# Proxy War data

This directory contains a reproducible, replay-derived dataset for comparing
our policy with current Proxy War competitors.

## Refresh

```bash
npm run data:refresh
```

The default refresh collects the latest 20 completed Competition rounds. Use a
different window with:

```bash
node scripts/collect-proxywar-data.mjs --rounds 40
npm run data:analyze
```

Requirements: `uv`, the pinned `coworld==0.1.28` CLI login, Node.js 24+, and
DuckDB 1.5+.

## Layout

- `cache/replays/`: downloaded public replay blobs; ignored by Git.
- `staging/`: normalized NDJSON; ignored by Git.
- `processed/rounds.parquet`: one row per completed competition round.
- `processed/episodes.parquet`: one row per hosted match.
- `processed/participants.parquet`: one row per player seat and match.
- `processed/decisions.parquet`: one row per accepted or rejected agent decision.
- `processed/manifest.json`: source URLs, SHA-256 hashes, collection time, and row counts.
- `analysis/`: versioned aggregate CSVs and quality checks generated by DuckDB.

Raw replay text, action labels, model reasons, and chat are excluded from the
processed decision table. They are untrusted opponent-controlled or
model-generated text and are unnecessary for the current statistics.

## Core grain and keys

| Table | Grain | Key |
| --- | --- | --- |
| rounds | round | `round_id` |
| episodes | match | `episode_id` |
| participants | player seat in a match | `episode_id`, `participant_position` |
| decisions | global decision sequence in a match | `episode_id`, `sequence` |

Run `duckdb < analytics/meta.sql` after collection. Every check in
`analysis/data_quality.csv` should report zero failures before using the
statistics to revise the policy.

The current window spans two formats. Rounds 163-180 are two-player matches;
rounds 181 onward use four-player FFA. Use the `player_count` column or the
`ffa_*.csv` outputs for current-meta decisions.
